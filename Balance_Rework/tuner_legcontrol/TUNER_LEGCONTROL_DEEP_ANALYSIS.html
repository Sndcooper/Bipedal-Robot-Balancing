Primary diagnosis

The robot is not failing because one PID number is wrong.

The current Stage-2 firmware has a pitch PID inside a zero-velocity PI loop. It does not yet contain a position loop, so returning to the original location is impossible by design. When the outer loop is enabled, its ±6° lean authority is larger than the inner controller can reproduce without PWM saturation. When the chassis is held by hand, the physical feedback path is broken and both loops accumulate commands against the support.

Most important finding: several September 10 runs changed VP and TG while telemetry showed ATE:0. In that state the firmware forces lean_cmd = 0, so those gain changes did nothing.

Current hardware and control architecture

Sensors

MPU6050 + wheel encoders

MPU6050 on PB6/PB7. Complementary-filter pitch uses accelerometer angle plus gyro Y. Single-channel interrupt decoding produces raw left/right counts with mirrored physical signs.

Actuation

L298N + two JGA gearmotors

Wheel PWM on PA1/PA0. Gearbox friction, L298N voltage loss, motor mismatch, and unmeasured breakaway PWM can turn small commands into stick-slip motion.

Legs + radio

Four AX-12s + 3DR telemetry

AX-12 bus on USART2 at 1 Mbps. 3DR radio on USART3 at 115200. Leg motion changes center of mass and must be held fixed during wheel tuning.

Evidence from the serial logs

Saturation

VP = 0.02 is far too aggressive

A ±6° lean limit is reached at only 300 counts/s. The logs contain 500–760 counts/s and repeated ±6° trim, with pitch swinging roughly −9° to +7°. That is effectively bang-bang behavior.

Range mismatch

Outer request exceeds inner authority

At Kp = 78, proportional action alone reaches 255 PWM at 3.27° error. A 6° request implies 468 PWM before D or I. The outer loop is allowed to demand a state the inner loop cannot linearly produce.

Integral behavior

Inner I reaches its cap extremely quickly

With Ki = 650, the integral-state limit is 64/650 = 0.09846 degree·seconds. The logs repeatedly show approximately ±0.0985. A 5° error reaches that cap in about 20 ms.

Hidden yaw

The averaged encoder signal hides disagreement

One long run ends near left −14,397 and right −13,640 raw counts. The normalized forward average is only a few hundred counts, while the differential component is about 14,000 counts. The wheels can counter-rotate while the cascade thinks forward velocity is near zero.

Mode ambiguity

“Auto-Trim” disables both velocity P and I

TE0 forces total lean command to zero. On September 10, multiple VP/TG changes happened while ATE was off. The GUI label suggests only the integrator is affected, which is incorrect.

Servo disturbances

AX-12 health is secondary but real

Temperatures are not excessive, but logs include nonzero status flags and high consecutive fail counts. An unexpected joint movement changes the plant, so resolve these separately from PID tuning.

Why “calibrated pitch is standing” is misleading

Calibration averages the accelerometer angle in the pose currently being held, stores it as the offset, and sets the filtered pitch to zero. A supported 2° lean therefore becomes the new 0°. The logs show offsets varying from roughly −0.50° to −1.84° over a short period, with another calibration near +8.79° followed by −1.29°.

Do not do this

Rigid hand support

The wheels move but the body cannot pitch naturally. Controllers integrate against your hand, wheel velocity rises, lean saturates, and releasing pressure produces a jerk.

Use this instead

Slack overhead catcher

Place the robot at a measured physical upright, calibrate stationary with motors off, then let pitch, translation, and yaw move freely. The tether should act only after the robot is already falling.

What to focus on, in order

1

Make the experiment physically valid

Freeze leg pose, use a slack tether, calibrate at measured upright with motors off, and stop holding the body during captures.

2

Verify both drive channels

Measure encoder counts/revolution, left/right normalized direction, minimum breakaway PWM in both directions, and motor response mismatch.

3

Restore a trustworthy inner loop

Velocity loop off. Use the known-good single-loop Kp/Kd baseline. Temporarily set pitch Ki to zero, tune PD without repeated saturation, then add only necessary integral.

4

Tune velocity P alone

Set Ki_trim = 0. Start Kp_vel ≈ 0.0005–0.001, limit lean to ±1° or ±1.5°, and add a lean slew-rate limit. Do not start at 0.02.

5

Add conditional velocity integral

Try a small value only after P works. Freeze/back-calculate integration whenever lean or PWM is saturated.

6

Add position P last

Use (encL - encR)/2, tightly limit target velocity, and keep the position bandwidth below the velocity bandwidth.

7

Make the GUI and telemetry truthful

Rename the mode, split P/I enables, synchronize live gains on connect, clamp parameters in firmware, and log raw pitch, gyro, both wheel speeds, controller terms, output, and saturation flags.

Next-run checklist

Secondary code issues

IMU robustness

The code does not verify that all 12 MPU6050 bytes arrived before reading. It also does not calibrate gyro bias. The documentation says 400 kHz I²C, but setup only calls Wire.begin().

GUI synchronization

On connect, the GUI requests servo state but not a complete balance-controller state. Slider defaults can therefore differ from the parameters actually running on the MCU.

Telemetry bandwidth

Control executes at 100 Hz while radio telemetry is about 10 Hz. Fast chatter and one-tick saturation are invisible. Use a short triggered 50–100 Hz diagnostic capture.

Documentation drift

The fusion README still describes encoder values as display-only and the controller as single-loop. The implementation changed in 204e9ea, so current source and logs must take precedence.
